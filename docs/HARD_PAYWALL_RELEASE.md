# Hard Paywall — release contract

**Status: code staged in feature branch, production NOT enabled.**

## Scope
- Web/PWA: opens `InstantStudy™ → IStudy™` motion, then the user sees the editorial onboarding and premium plan choices when the gate is active; a paid entitlement (Plus, Unlimited, Family, Instant One) allows the existing Orbital UI.
- Web backend: ALL `POST /api/study` actions require an active account-bound entitlement when enabled, not just the `prepare` action. The `paywall_status` action is a read-only status probe and returns no secrets. Unknown actions cannot skip the gate.
- Trusted API: all non-admin `/api/v1` calls require timestamped HMAC-SHA256 proof generated by the Web BFF when enabled. The same signing secret is shared only by the two server deployments.
- MCP: the old shared-bearer integration is **disabled** in hard-paywall mode until OAuth per learner exists. This means ChatGPT plugin availability must be reworked before selling plugin access.
- Flutter: includes a native editorial gate for design review behind `--dart-define=INSTANTSTUDY_NATIVE_HARD_PAYWALL_ENABLED=true`. **Do not enable this in a released mobile app.** No StoreKit, Google Play Billing, receipt validation or purchase restoration is installed yet; showing an external Paddle purchase link inside the mobile app is intentionally avoided.

## Required launch configuration

### Vercel instantstudy-web (BFF)
- `INSTANTSTUDY_HARD_PAYWALL_ENABLED=true` (default false)
- `INSTANTSTUDY_BFF_SIGNING_SECRET=` a newly generated random 32+ character value, never stored in Git
- `INSTANT_PAY_URL=` trusted HTTPS origin of Instant Pay
- `INSTANTSTUDY_API_URL`, `INSTANTSTUDY_API_KEY` existing service credentials
- `VITE_INSTANT_ACCOUNT_LOGIN_URL=` trusted HTTPS account sign-in/registration URL with return to `/app` and an actual provisioned `instant.account.session`. This app does NOT implement its own login provider.

### Vercel instantstudy-api (study/MCP backend)
- `INSTANTSTUDY_HARD_PAYWALL_ENABLED=true` (default false)
- `INSTANTSTUDY_BFF_SIGNING_SECRET` **exact same** secret as Web BFF
- `INSTANTSTUDY_API_KEY` existing private bearer

**Set and deploy both flags together** only after identity, payment + webhook and consumer restore paths have been verified. Do not enable only one service: the API would reject regular calls or could expose an unsigned bypass. Do not ship live without native payment verification. A remote service environment being configured does not prove the entitlement DB is actually ready.

## Required E2E checks before production

1. New account registration produces a verified Instant Account session and returns to `/app`; no tokens are accepted as proof by the front-end alone.
2. Unauthenticated, fake ID and inactive subscriber: study API returns 401/402 before any upstream study operation.
3. Trial **only if Paddle actually provisions a trialing active entitlement**; confirm retry, cancellation, expired trial, failed payment, account mismatch and family membership.
4. Web purchase in Paddle must reliably map to the same Instant Account identity (customer ID/email matched to verified account), and signed Paddle webhooks must upsert the proper entitlement. Current checkout does not include end-to-end guaranteed account binding; solve and test this before enabling.
5. After payment, return and choose **Já assinei — verificar acesso**. Grant access only after Instant Pay confirms the entitlement, not after a checkout redirect or localStorage flag.
6. A forged request to `/api/study`, a direct API Bearer request without HMAC and the legacy MCP must not unlock a paid account.
7. Revalidation when returning to foreground must close the app if subscription expired. Changing study scenes must not replay the splash or mount a second Siri Orb.
8. Vercel CI, TypeScript build, Flutter tests, Paddle sandbox checkout, real entitlement in Neon, mobile screen sizes, localization/accessibility and OWASP must pass. Paid renewals, tax and cancellation disclosures must match the actual checkout provider.
9. For iOS and Android add compliant Apple/Google in-app purchases, a backend-validated receipt/entitlement sync, `Restore Purchases` and subscription management before enabling the native flag.

## Product decision
This branch replaces freemium with **hard paywall only when the feature flag is enabled**. Pricing copy does not promise a 7-day trial if provider eligibility/offer isn't confirmed. This is a staged implementation rather than a claim of a working payment funnel.

## Implementation
- `apps/web/src/HardPaywallGate.tsx`, `apps/web/src/hard-paywall.css`: onboarding, plans, entitlement recheck.
- `apps/web/api/_hardPaywall.js`, `apps/web/api/study.js`: fail-closed policy and signed study API requests.
- `apps/mcp-server/src/hardPaywallSignature.ts`, `server.ts`: signature enforcement and MCP block.
- `apps/flutter_app/lib/native_hard_paywall.dart` and `main.dart`: native implementation shell, disabled.
- `apps/web/api/hardPaywall.test.js`, `apps/mcp-server/src/hardPaywallSignature.test.ts`: security regression tests.
